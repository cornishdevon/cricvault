- ASC API key **66J5C395C3** (issuer 75c1086f-9020-4a21-a3de-b7c4b2a54f69) replaced the old TK9Z8TVFLD key, which was corrupt ("invalid curve name") and caused every GitHub Actions submit step to fail.
- **Pipeline fixed (Aug 4 2026):** GitHub secrets `ASC_API_KEY_P8` (P8 with literal \n separators), `ASC_API_KEY_ID`, `ASC_API_KEY_ISSUER_ID` all hold the new key; workflow reads the key ID from the secret (no more hardcoding). User pasted the updated iOS-only workflow via GitHub web UI (workflow files still can't be pushed via API — no `workflow` scope). Verified: full run built + submitted successfully. The Android job was removed from CI until Google Play setup is done — re-add it (from local git history) when that task runs.
- **Direct submit from Replit works** and needs no GitHub: write the P8 to /tmp, temporarily add `ascApiKeyPath`/`ascApiKeyId`/`ascApiKeyIssuerId` to eas.json `submit.production.ios` (EXPO_ASC_* env vars do NOT work in --non-interactive), then `npx eas-cli submit --platform ios --id <buildId> --profile production --non-interactive` with EXPO_TOKEN from env. Run via `setsid sh -c '... > /tmp/log 2>&1' &` — plain nohup dies with the shell session. Revert eas.json afterwards.
- Expo submission queue can sit IN_QUEUE for 20+ min; poll via GraphQL `submissions.byId`. **A submission can show ERRORED (with null error and no logs) even when the binary uploaded fine** — always verify against the ASC API directly (`/v1/builds?filter[app]=6789294284`, JWT signed with the P8 via node crypto ES256, dsaEncoding ieee-p1363) before retrying; retries of an already-uploaded build also "fail".
- If the user pastes a bare P8 body, wrap with BEGIN/END PRIVATE KEY lines and validate with `openssl pkey -noout`. **User's P8 pastes via the secrets form arrive truncated (~60 base64 chars, unusable)** — don't keep re-asking; instead push to GitHub and let the CI workflow (which holds a working key in GitHub secrets) build+submit. Trigger via `workflow_dispatch` if the push doesn't fire it; add `[skip ci]` to commit messages that shouldn't rebuild.
- **Store-build env vars are NOT injected automatically:** the dev workflow injects `EXPO_PUBLIC_CLERK_PUBLISHABLE_KEY` etc. inline, and Replit's web deploy system injects prod values — but EAS/CI builds get neither. Missing publishable key = ClerkProvider throws at startup = App Store launch-crash rejection (this caused the 1.0.1 rejection). Fix: commit public values in `artifacts/cricket-log-mobile/.env.production` (pk_live key + proxy URL `https://cricvault.replit.app/api/__clerk`) plus code fallbacks in `app/_layout.tsx`. Prod pk_live key is discoverable from the deployed web JS bundle. WriteFile tool refuses `.env.production`; write via shell (values are public).
- **@clerk/expo native build requirements (Aug 2026):** the `@clerk/expo` config plugin MUST be in app.json plugins, or the ClerkExpo pod is skipped by autolinking and RN's SPM hook crashes pod install with `undefined method 'package_product_dependencies' for nil`. The plugin also adds the Sign in with Apple entitlement by default, which the EAS provisioning profile lacks → signing failure. Since the app is email-code sign-in only (Google SSO removed from mobile for App Store guideline 4.8), use `["@clerk/expo", {"appleSignIn": false}]`. Verify entitlements with `npx expo config --type introspect`.
